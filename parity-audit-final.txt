## Severity Rubric

| Level | Definition | Example |
|-------|-----------|---------|
| **Critical** | Breaks core user-facing functionality (can't play video, can't browse content) or causes data loss | Race conditions setting state on unmounted components; no ESLint means broken imports undetected |
| **High** | Degrades a primary feature (wrong audio language, lower quality video, can't translate UI) | Source sorting picks wrong quality; i18n not wired into player |
| **Medium** | Missing secondary feature, code maintainability gap, or UX annoyance | No debounce hook (multiple inline implementations); missing caching layer |
| **Low** | Cosmetic only, DX improvement, or edge case | Prettier indent width; glass-filter SVG vs CSS blur; youtube.com vs youtube-nocookie.com |

*Items marked with [Superior] indicate our project has a better implementation than the reference.*

## Confidence Categories

- **[Verified]** — Directly compared both implementations at the code level. Can cite specific file paths and line numbers.
- **[Inferred]** — Feature presence or behavior deduced from file naming, directory structure, or import patterns, but the implementation was NOT read line-by-line. Typically applies to features assumed from the reference's file tree that we did not fully analyze (e.g., "show likely has X based on file type naming").
